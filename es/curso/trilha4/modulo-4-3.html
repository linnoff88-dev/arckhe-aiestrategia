⚙️ Orquestación, reanudación y diagramas que venden

El pegamento que une las tres fases. Al final, la Fábrica funciona de principio a fin.

🎛️ El orquestador del pipeline

El orquestador es el director: inicia Investigación → Síntesis → Generación en orden, y cada etapa confirma la conclusión antes de que empiece la siguiente. Nada avanza a ciegas: si la Fase 1 no terminó, la Fase 2 no se ejecuta.

1.
Recibe entradas. Nombre + descripción de la empresa (y la profundidad de la investigación).
2.
Investiga, sintetiza, genera. Las tres fases en secuencia, cada una alimentando a la siguiente.
3.
Confirma y empaqueta. Renderiza diagramas, organiza carpetas y prepara el paquete para descargar.

💡 Confirmar por etapa es lo que salva

La confirmación por fase no es burocracia: es lo que hace que el pipeline retomable. Como cada etapa marca "completada", una caída a mitad del proceso no te obliga a repetir (ni a volver a pagar) lo que ya estaba listo.

💾 Checkpoints y state.json

O state.json es la memoria de la Fábrica. Vive en output/{empresa}/ y guarda la fase actual, el estado de cada uno de los entregables y el costo total acumulado de la sesión.

// output/stripe/state.json

{
  "company_name": "Stripe",
  "current_phase": "synthesis",
  "phases": {
    "research":   { "status": "complete" },
    "synthesis":  { "status": "in_progress" },
    "generation": { "status": "pending" }
  },
  "deliverables": {
    "01_tech_inventory": { "status": "complete", "path": "..." },
    "06_quick_wins":     { "status": "pending" }
  },
  "total_cost": 0.0773
}

📍 Fase actual

current_phase dice exactamente dónde se detuvo la Fábrica.

✅ Estado por entregable

Cada uno de los 15+ documentos marca complete / pending / failed.

💵 Costo acumulado

total_cost suma cada llamada: el control del presupuesto en tiempo real.

💡 Sin checkpoint, no puedes retomar

O state.json es la condición para todo lo que viene después. Es lo que transforma «hubo un error, lo perdí todo» en «hubo un error, continúo desde donde me quedé». Cada entregable que completa se guarda al instante.

🔁 Retomar cuando se llena el contexto

Las sesiones largas de Claude Code agotan el contexto; sucedió dos veces en la construcción de la Fábrica original. La solución no es cruzar los dedos para que no ocurra; es abrir una sesión nueva y retomar desde la lista de tareas almacenada en state.json.

// ¿se llenó el contexto? nueva sesión, mismo comando

# ver onde parou
python -m strategy_factory.main status "Stripe"

# retomar de onde o state.json marcou
python -m strategy_factory.main resume "Stripe"
# → pula research (complete), continua synthesis, depois generation

✓ Con reanudación

  • ✓Una nueva sesión lee el state.json y continúa
  • ✓Omitir fases ya complete — no vuelve a pagar
  • ✓Usa el research_cache.json en vez de volver a investigar

✗ Sin reanudación

  • ✗Se llena el contexto → todo empieza desde cero
  • ✗Vuelve a pagar la investigación cada vez que algo falla
  • ✗Las sesiones largas se convierten en un callejón sin salida

💡 La documentación cuesta pocos tokens

Incluso con el plan de US$20 de Anthropic puedes hacer mucho, siempre y cuando divide las solicitudes. Construir en público es mostrar el desorden: límites de contexto, errores de API, un nombre de modelo equivocado en la documentación. Retomar desde la lista de tareas es la habilidad que te permite terminar incluso cuando algo se traba.

🪢 Mermaid: estado actual vs. futuro

El prompt de diagramas genera dos flowcharts que cuentan la historia de la transformación: el estado actual (el stack actual, con los cuellos de botella marcados) y el estado futuro (la arquitectura habilitada por IA). Es el "antes y después" lo que vende.

// ejemplo de Mermaid: estado actual vs. futuro

flowchart TB
  subgraph Atual["Estado Atual"]
    DS1[Planilhas soltas] --> CS1[CRM legado]
    CS1 --> U1[Vendas]
    CS1 -. gargalo .-> X[(Dados em silos)]
  end

  subgraph Futuro["Estado Futuro · IA"]
    DL[Plataforma de Dados Unificada] --> AI1[Copiloto de Vendas]
    DL --> AI2[Previsão de Churn]
    AI1 --> U2[Vendas]
    AI2 --> U3[Sucesso do Cliente]
  end

  Atual ==>|transformação| Futuro

📉 Estado actual

  • •Fuentes de datos y sistemas heredados
  • •Puntos de integración frágiles
  • •Cuellos de botella conocidos marcados en rojo

📈 Estado futuro (IA)

  • •Plataforma de datos unificada
  • •Capa de servicios de IA/ML
  • •Aplicaciones potenciadas y flujos automatizados

💡 La diapositiva decisiva

Un ejecutivo no lee tres páginas de texto, pero entiende el «antes y después» en cinco segundos. Marcar los cuellos de botella en el estado actual crea tensión; mostrar el estado futuro ofrece la solución. Ese par de diagramas suele ser la diapositiva que consigue la aprobación del proyecto.

🖼️ Renderizar Mermaid → PNG

El cliente no abre un archivo .mmd — abre una imagen en la diapositiva. El mermaid_renderer transforma el código en un PNG real para incluirlo en el PPTX. Y si falla la renderización, entra en juego la degradación gradual: omite la imagen y conserva el markdown.

1

mermaid_renderer (en el pipeline)

Toma el código generado por el prompt de diagramas y exporta un PNG para mermaid_images/. Es el flujo automático de la Fábrica.

2

Skill beautiful-mermaid

Renderiza Mermaid como SVG y PNG con un acabado cuidado: ideal cuando quieres un diagrama atractivo, fuera del pipeline.

3

eraser.io

Editor en línea para ajustar el diagrama manualmente y exportarlo — ideal para un retoque rápido antes de la reunión.

💡 PNG en la diapositiva, fuente con control de versiones

Guarda el .mmd en recursos/diagramas/ (versionable) y entrega el PNG en el deck. Así puedes editar el texto del diagrama cuando cambie el proyecto, sin rehacer la imagen desde cero.

📦 Empaquetar para descargar

La Fase 3 cierra el ciclo: organiza todo en carpetas y empaqueta el paquete completo para descargar. Entregar es la mitad del trabajo: un paquete bien organizado es lo que hace que el cliente sienta que pagó por algo serio.

// output/{empresa-slug}/ — la estructura entregada

output/stripe/
├── markdown/          # 15 .md (os entregáveis)
├── presentations/     # 2 .pptx (resumo + achados)
├── documents/         # 2 .docx (relatório + SOW)
├── mermaid_images/    # PNGs dos diagramas
├── research_cache.json
└── state.json
1.
Guarda los archivos Markdown. Los 15 entregables en markdown/, el conocimiento interno.
2.
Genera PPTX y DOCX. Deck ejecutivo, hallazgos completos, informe final y SOW: la entrega refinada.
3.
Lo empaqueta todo. Diagramas renderizados juntos, listos para descargar en la webapp.

🎯 Misión 4.3 — La Fábrica de principio a fin + diagramas

Ejecuta el pipeline completo para la empresa de las misiones anteriores y genera los diagramas del estado actual frente al futuro.

  1. Pídele a Claude Code que ejecutar la Fábrica de principio a fin (Investigación → Síntesis → Generación).
  2. Si el contexto se llena, abre una sesión nueva y usa resume "Empresa" — confirma que omitió lo que ya estaba listo.
  3. Abre el state.json y consulta todas las fases en complete e o total_cost.
  4. Renderiza los diagramas (renderer, beautiful-mermaid o eraser.io) y revisa los PNG en mermaid_images/.

Éxito: la carpeta output/{empresa}/ con los 19 entregables y los diagramas renderizados, por < US$1. Lo que obtuviste: la Fábrica funcionando de principio a fin: el motor que la Trilha 5 convierte en una oferta y lleva al cliente.
